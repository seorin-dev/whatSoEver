# 점심팔자 (가칭) — 사주 기반 팀 점심 메뉴 추천 서비스 설계

> 해커톤: 1박 2일 (~24시간) · 1인 개발 + Claude Code
> 작성일: 2026-06-11

## 1. 컨셉

팀원들의 사주팔자(생년월일시)로 **팀 궁합과 오행 분포**를 계산하고, 오늘 날짜의
일진(日辰)을 반영해 **"오늘 우리 팀이 함께 먹으면 좋은 점심 메뉴"**를 추천하는 웹 서비스.

- **톤**: 재미·바이럴 중심. 명리학 용어는 근거 장치로만 쓰고, 해설은 밈 톤 유머.
  예: "팀 전체 화기운 78%. 오늘 회의에서 언성 높아질 확률 200%. 물냉면으로 진화하세요."
- **대상**: 2~8명 그룹 (팀 점심 시나리오). 한 명(총무)이 멤버 전원의 정보를 입력.
- **결과물**: 음식 메뉴 추천 1~3위. 실제 식당 연결은 TO-BE(범위 외).

## 2. 기능 목록 (MVP 확정)

| # | 기능 | 설명 |
|---|------|------|
| 1 | 팀 입력 | 팀 이름 + 멤버(이름, 생년월일, 시진은 선택 — 모르면 정오 기준) 2~8명 입력 |
| 2 | 룰렛 연출 | 음식 후보 8칸 룰렛이 돌다가 **API가 확정한 1위 메뉴에 멈춤**. API 대기(2~5초)를 흡수 |
| 3 | 메뉴 추천 | 1위 크게 + 2·3위도 해설 한 줄씩 함께 표시 |
| 4 | 유머 해설 | LLM이 생성하는 밈 톤 추천 이유 + 팀 총평 |
| 5 | 팀 오행 차트 | 멤버 오행 합산 도넛 차트, 과다·부족 기운 요약. 멤버 클릭 시 개인 오행 |
| 6 | 오늘의 운세 | 오늘 일진 간지를 계산에 가중 반영 → 같은 팀도 매일 결과가 달라짐 |
| 7 | 최고/최악 궁합 페어 | 멤버 1:1 궁합 매트릭스에서 최고·최악 페어 추출 + 유머 코멘트 |
| 8 | 팀 저장 | 로컬스토리지에 팀 저장, 첫 화면에서 불러오기. 서버 DB 없음 |
| 9 | 다시 뽑기 | 결과 화면에서 재추천 (후보 풀에서 다른 조합) |

**제외(논의 후 미채택)**: 팀 케미 점수, 결과 카드 이미지 공유, 멤버 역할 부여, 못 먹는 음식 필터.
**TO-BE**: 근처 실제 식당 연결(네이버 지역 검색), 링크 공유로 각자 입력하는 방 모드.

## 3. 아키텍처 (접근 B: 규칙 기반 계산 + LLM 해설)

**스택**: Next.js(App Router) + TypeScript + Tailwind CSS · Recharts · lunar-javascript · Claude API · Vercel 배포

3개 레이어:

1. **사주 엔진** — 클라이언트 순수 TS 모듈. 결정적 계산 (같은 입력 → 항상 같은 출력).
2. **추천 API** — `/api/recommend` 단일 엔드포인트. 계산 결과 JSON → Claude API(구조화 출력) → 메뉴 확정 + 해설 생성. API 키는 서버에만.
3. **UI** — 입력 → 룰렛 → 결과 3화면. 팀 정보는 로컬스토리지.

```
[입력] 팀원 이름+생년월일(+시진)
   ↓ 사주 엔진 (클라이언트, 즉시)
[오행/궁합/일진 계산 결과] ──→ /api/recommend ──→ Claude API
   ↓ 룰렛 연출 (2~5초)                  ↓
[결과 화면] ←── 1~3위 메뉴 + 해설 JSON ←─┘
```

## 4. 사주 엔진 로직

1. **개인 사주**: lunar-javascript로 생년월일(+시진) → 사주 네 기둥 간지 → 천간·지지를
   오행(목화토금수)으로 매핑해 개인 오행 분포 계산. 시진 미입력 시 시주 제외(6글자).
2. **팀 오행**: 멤버 분포 합산 → 과다(≥35%) / 부족(≤10%) 판정.
3. **1:1 궁합**: 멤버 쌍별 일간(日干) 기준 상생(+)/상극(−) 점수화 → 최고/최악 페어.
4. **오늘의 일진**: 오늘 날짜 간지를 팀 오행에 가중치로 반영.
5. **메뉴 스코어링**: 음식 DB(40~60개 메뉴, 오행 속성 태깅 — 예: 물냉면=수,
   매운탕=화+수, 비빔밥=균형)에서 부족 기운 보충 메뉴를 스코어링 → 상위 후보를 API에 전달.

## 5. 에러 처리 (데모 생존 전략)

- Claude API 8초 타임아웃 / 실패 시 → **폴백**: 엔진 스코어링 1~3위를 그대로 사용,
  해설은 오행 조합별 사전 작성 템플릿 풀에서 선택. UI는 폴백 여부를 구분하지 않음.
- 입력 검증: 생년월일 범위(1900~현재), 멤버 2~8명, 이름 필수. 클라이언트에서 즉시 피드백.

## 6. 디자인 컨셉

- **질감**: 픽사 〈엘리멘탈〉 — 어두운 배경(엘리멘트 시티의 밤) + 네온 글로우 발광. (시안 A 확정)
- **오행 캐릭터 5종** (SVG, 눈·입·팔다리 달린 꼬마 캐릭터):
  🔥 불똥이(화) · 💧 방울이(수) · 🌱 새싹이(목) · ⚙️ 반짝이(금) · ⛰️ 흙돌이(토)
- **캐릭터 활용**: 입력 화면 인사 → 룰렛 둘레 응원 → 결과 화면에서 과다 기운 캐릭터가
  메인 멘트 담당 ("오늘은 불똥이가 너무 많아!").
- 차트·룰렛·카드 모두 다크 배경 위 글로우 컬러로 통일.

## 7. 화면 플로우

1. **입력**: 로고/마스코트 + 팀 이름 + 멤버 카드 추가 UI + (저장된 팀 불러오기) + CTA
2. **룰렛**: 음식 후보 8칸 룰렛 회전, 캐릭터 응원, 계산된 오행 멘트 한 줄씩 노출 → 1위에 멈춤
3. **결과**(스크롤 1페이지): 일진+추천 1위/유머 해설 → 2·3위 칩+한줄평 → 팀 오행 차트
   → 최고/최악 페어 → [다시 뽑기 / 팀 저장]

## 8. 테스트 전략

- **사주 엔진 단위 테스트 집중**: 알려진 날짜의 간지 검증(만세력 대조), 오행 합산,
  궁합 매트릭스, 메뉴 스코어링.
- API: 정상 + 폴백 경로 각 1개.
- UI: 수동 확인 (해커톤 범위).

## 9. 구현 우선순위 (24시간 배분 가이드)

1. 사주 엔진 + 음식 DB (코어, 테스트 포함)
2. 입력 → 결과 기본 플로우 (스타일 최소)
3. 추천 API + Claude 연동 + 폴백
4. 룰렛 연출 + 디자인 시스템(다크 네온 + 캐릭터 SVG)
5. 오행 차트 + 페어 카드 + 팀 저장
6. 폴리시·배포(Vercel)·데모 리허설
